# 层级树（Hierarchy Tree）

## 1 适用场景

层级归属关系的表达：文件夹与文件、设计稿里的图层与节点

## 2 表达原则

| 内容 | 必需条件 | 表达规则 |
| --- | --- | --- |
| 树 | 始终必需 | [§2.1](#21-树) |
| 注释 | 需要补充对应项含义时 | [§2.2](#22-注释) |

### 2.1 树

使用 `text` 代码块表达树
顶层是一个根或几个并列的项，不是实际名字的用 `<占位>`
文件夹名以 `/` 结尾
子项用树形连线接在父项下，同级左对齐
同一层先排文件夹，再排文件，各组内按名字排，有编号前缀的按编号排

只画与要说明的事相关的项，其余用 `…` 一行代过，几个同类的小项可以并在一行

### 2.2 注释

每条注释写在对应行的右侧，一行一句
同一棵树里的注释对齐到同一列
注释只对其对应的行内容做出解释说明

## 3 示例：文件结构

```text
<Web 应用仓库>/
├─ docs/
│  ├─ design/
│  │  ├─ module-order/       订单模块的契约、实现与测试
│  │  ├─ architecture.md     模块职责与协作
│  │  └─ interaction.md      用户场景与交互
│  └─ README.md              文档索引
├─ src/
│  ├─ order/                 订单模块源码
│  └─ …
└─ README.md                 项目门面
```

## 4 示例：Figma 层级结构

```text
<页面>                        Page
├─ <用户场景>                 Section
│  └─ <设计模块>              Frame
│     └─ <区域>               Frame
│        ├─ Default           Instance
│        └─ Bonus             Instance
└─ Implementation Note        Section
   └─ <设计模块>              Frame
      ├─ Target Link          Text
      └─ Responsive Sizing    Text
```

## 5 检查条件

### 5.1 树不完整或不真实

- [ ] 每个节点只出现一次，名字与实际一致，不是实际名字的是 `<占位>`
- [ ] 文件夹名以 `/` 结尾，同一层文件夹在前、文件在后，各组内按名字或编号排
- [ ] 省略的部分用 `…` 标出

**反例**

```text
command/
├─ README.md
└─ 各命令文件
```

「各命令文件」不是真实的文件名，读者不知道有哪些文件

### 5.2 文字复述了树已表达的内容

- [ ] 注释只解释所在行，没有复述这一行的名字
- [ ] 代码块外的文字没有逐项复述树里的节点

**反例**

```text
docs/
├─ README.md            README 文件
└─ design/              design 文件夹
```

docs 文件夹里有 README.md 和 design 文件夹

注释复述了本行的名字，树下面的一句话又复述了整棵树
