# 文档组：ops-guide

## 1 适用场景

适用于本工程需要向运营或数据平台使用者提供数据采集、分析方法或运营动作指导的项目

## 2 文档组成

运营指南目录与三类指南均按需建立
没有指南需求时，可以不建立 `ops-guide/` 目录
文档放在工程类型规定的运营指南目录，选用条件与文件名见下表

```text
ops-guide/
├─ README.md
├─ data-collection.md
├─ data-analysis.md
└─ ops-actions.md
```

| 文件 | 必要条件 | 职责 |
| --- | --- | --- |
| `README.md` | 建立运营指南目录 | 说明已选用指南的用途、关系与执行入口 |
| [data-collection.md](../documents/data-collection.md) | 需要本工程提供数据获取与定义说明 | 说明原始数据来源、获取方法与数据定义 |
| [data-analysis.md](../documents/data-analysis.md) | 需要本工程提供指标分析指导 | 汇总指标，逐项说明分析方法与可选的可视化方式 |
| [ops-actions.md](../documents/ops-actions.md) | 需要本工程提供运营动作指导 | 说明允许执行的动作、操作方法与结果确认方式，按需说明操作依据 |

README 按 [readme 文档设计](../documents/readme.md)组织入口与导航
已选用的指南分别按自身职责组织内容，具体章节结构由各自的文档设计规定
数据获取涉及导出、解密或解析时，操作说明归入 [data-collection](../documents/data-collection.md#2-文档结构) 的获取方法

### 2.1 输入输出关系

1. 分析指南引用所需原始数据的来源与定义
2. 动作指南按需说明操作依据
   依赖分析指标时，引用一个或多个对应指标章节
3. 动作指南说明结果确认方式
   需要通过数据评价动作效果时，引用对应的数据来源与分析指标

### 2.2 共用内容

1. 引用已有工程定义
   数据契约、接口与配置约束沿用对应设计
   工程产生的事件与参数引用 [instrumentation](../documents/instrumentation.md)，不重复定义
2. 集中定义共用内容
   优先在负责该内容的指南中统一说明
3. 保留当前场景的信息
   引用共用方法时，写清选用的方法、适用条件、输入或参数，以及预期结果

## 3 治理顺序

1. 确定本工程需要提供的指南，按[文档组成](#2-文档组成)选用文件
   核对所需数据、分析方法与允许执行的动作，定位已有定义
2. 需要数据获取与定义说明时，编写数据采集指南
   明确原始数据来源、获取方法与数据定义
3. 需要指标分析指导时，编写数据分析指南
   汇总指标，逐项说明分析方法与可选的可视化方式
   所需原始数据来源或定义缺失时，补齐对应内容或引用
4. 需要运营动作指导时，编写运营动作指南
   按章说明允许执行的动作、操作方法与结果确认方式
   依赖分析指标时，补齐对应内容或引用
5. 完善 README 与跨文档引用
   汇总已选用指南的用途与执行入口，核对各自所需的输入及结果确认方式

工程能力或业务决定不足时，记录具体缺口，交由输入提供方确认后继续编写
指南不自行补出未经确认的工程能力
本章规定文档治理顺序，实际运营的执行周期由各篇指南规定

## 4 检查条件

- [ ] 目录与指南按本工程实际需要选用，文件名符合文档组成
- [ ] 建立目录时，README 说明已选用指南的用途、关系与执行入口
- [ ] 选用数据采集指南时，原始数据来源、获取方法与数据定义齐全
- [ ] 选用数据分析指南时，指标汇总能够定位到各指标章节，分析方法明确
- [ ] 选用运营动作指南时，允许执行的动作、操作方法与结果确认方式明确
- [ ] 通过数据评价动作效果时，所需数据与分析指标能够定位
- [ ] 分析指南引用所需原始数据，动作依赖分析指标时引用对应指标章节
- [ ] 共用口径与规则只在一处定义，引用能够定位
- [ ] 引用共用方法时，适用条件、输入或参数及预期结果明确
- [ ] 指南与工程实际的数据、接口及操作能力一致
