# 文档组：ops-guide

## 1 适用场景

适用于以工程产生的数据支持分析判断与运营动作，并持续核对动作效果的项目

## 2 文档组成

数据采集、数据分析与运营动作分别承担独立职责，各用一篇指南说明
文档放在工程类型规定的运营指南目录，固定四个文件

```text
ops-guide/
├─ README.md
├─ data-collection.md
├─ data-analysis.md
└─ ops-actions.md
```

| 文件 | 职责 |
| --- | --- |
| `README.md` | 说明运营目标、三篇指南的关系与执行入口 |
| [data-collection.md](../documents/data-collection.md) | 说明原始数据来源、获取方法与数据定义 |
| [data-analysis.md](../documents/data-analysis.md) | 汇总分析指标，逐项说明分析方法与可选的可视化方式 |
| [ops-actions.md](../documents/ops-actions.md) | 按章说明允许执行的动作、操作方法与结果确认方式，按需说明操作依据 |

README 按 [readme 文档设计](../documents/readme.md)组织入口与导航
三篇指南分别按自身职责组织内容，具体章节结构由各自的文档设计规定
运营目标通过跨文档引用串联

### 2.1 输入输出关系

1. 分析指南引用所需原始数据的来源与定义
2. 动作指南按需说明操作依据
   依赖分析指标时，引用一个或多个对应指标章节
3. 动作指南说明结果确认方式
   需要通过数据评价动作效果时，引用对应的数据来源与分析指标

### 2.2 共用内容

1. 引用已有工程定义
   数据契约、接口与配置约束沿用对应设计
   工程产生的事件与参数引用 [instrumentation](../documents/instrumentation.md)，不重复定义
2. 集中定义共用内容
   优先在负责该内容的指南中统一说明
   确需独立维护并供多个场景复用时，再单独成篇
3. 保留当前场景的信息
   引用共用方法时，写清选用的方法、适用条件、输入或参数，以及预期结果

## 3 治理顺序

1. 确定运营目标与三篇指南的输入输出关系
   明确分析要回答的问题及所需数据
   核对工程能够提供的数据与实际可采取的动作
2. 编写数据采集指南
   明确原始数据来源、获取方法与数据定义
3. 编写数据分析指南
   汇总指标，逐项说明分析方法与可选的可视化方式
   所需原始数据来源或定义缺失时，回到第 2 步补齐
4. 编写运营动作指南
   按章说明允许执行的动作、操作方法与结果确认方式
   依赖分析指标时补齐引用，指标缺失时回到第 3 步补齐
5. 完善 README 与跨文档引用
   修改影响其他指南时，同步更新输入输出与引用
   从运营目标出发，核对采集、分析、动作及下一轮数据之间的衔接

工程能力或业务决定不足时，记录具体缺口，交由输入提供方确认后继续编写
指南不自行补出未经确认的工程能力
本章规定文档治理顺序，实际运营的执行周期由各篇指南规定

## 4 检查条件

- [ ] 选用文档组后，固定四个文件均已建立，各自职责明确
- [ ] README 说明运营目标、三篇指南的关系，并提供有效入口
- [ ] 原始数据来源、获取方法与数据定义齐全，可直接查阅或通过引用定位
- [ ] 指标汇总能够定位到各指标章节，分析方法明确，可视化按需说明
- [ ] 允许执行的动作、操作方法与结果确认方式明确
- [ ] 通过数据评价动作效果时，所需数据与分析指标能够定位
- [ ] 分析指南引用所需原始数据，动作依赖分析指标时引用对应指标章节
- [ ] 共用口径与规则只在一处定义，引用能够定位
- [ ] 引用共用方法时，适用条件、输入或参数及预期结果明确
- [ ] 指南与工程实际的数据、接口及操作能力一致
