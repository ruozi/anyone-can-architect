# 文档设计：infrastructure

## 1 文档定位

本项目需要构建或依赖的基础设施设计，定义依赖范围、使用方式与资源结构

业务处理归对应业务设计文档
部署操作与环境配置交付归 [deployment](deployment.md)，安全论证归 [security](security.md)

## 2 文档结构

第一章用总览表列出基础设施、用途与详细设计入口
总览每行对应后续一个 chapter，每项基础设施单独成章

各章按实际内容[层层深入](../../skills/references/drill-down.md)，不预设资源类别与小节模板

- 定义资源位置、所用能力、使用方与接入方式
- 按资源类型定义所需的资源配置、数据结构与存储组织
- 按需定义权限、生命周期、迁移与一致性要求

结构示意：

```text
## 1 基础设施总览
## 2 <基础设施>
### 2.1 <具体内容>
#### 2.1.1 <具体内容>
## 3 <基础设施>
…
```

## 3 行文步骤

1. 盘点本项目需要构建或依赖的基础设施，列出用途与使用方
2. 定义每项基础设施的依赖范围与使用方式
   - 区分需要构建的资源与既有资源
   - 定位所用实例、数据库、桶、目录或服务端点
   - 定义所用能力、接入方式、配置项与身份权限
   - 引用既有接入契约及配置、凭据的交付位置
   - 凭据只记录来源，不记录实际值
3. 展开各项基础设施的资源配置，以及相关数据或对象的结构、标识与维护归属
4. 补充所需约束
   - 涉及持久数据时，定义保留、更新、删除与必要的恢复要求
   - 涉及迁移时，定义执行顺序、记录、事务边界、兼容性与失败处理
   - 涉及多处存储或派生数据时，定义来源、更新与一致性要求
   - 业务读写、重试与补偿流程引用对应业务设计文档
5. 按 [§2](#2-文档结构)组织各章，补充总览表的详细设计入口
   - 核对资源总览、具体设计与使用方引用的一致性

## 4 示例

```markdown
# 基础设施

## 1 基础设施总览

| 基础设施 | 用途 | 详细设计 |
| --- | --- | --- |
| PostgreSQL | 保存报告记录与对象引用 | [§2](#2-postgresql) |
| S3 | 保存生成的报告文件 | [§3](#3-s3) |
| 文件网关 | 为报告文件提供临时访问链接 | [§4](#4-文件网关) |

## 2 PostgreSQL

### 2.1 访问

报告模块使用数据库 `reporting` 的 `public` schema
应用身份可读写报告记录，结构变更由迁移身份执行

| 配置项 | 用途 | 来源 |
| --- | --- | --- |
| `REPORT_DB_HOST` | 数据库端点 | [数据库配置](deployment.md#21-postgresql) |
| `REPORT_DB_PORT` | 数据库端口 | [数据库配置](deployment.md#21-postgresql) |
| `REPORT_DB_USER` | 应用身份 | [数据库身份](deployment.md#21-postgresql) |
| `REPORT_DB_PASSWORD` | 应用身份凭据 | [数据库凭据交付](deployment.md#21-postgresql) |

### 2.2 报告数据

#### 2.2.1 报告记录

`reports` 每行保存一份已生成报告的身份与文件引用
维护归属为[报告模块](module-report/README.md)

| 字段 | 类型 | 允许空 | 默认值 | 含义 |
| --- | --- | --- | --- | --- |
| `report_id` | `UUID` | 否 | 无 | 报告模块生成的报告标识 |
| `object_key` | `TEXT` | 否 | 无 | S3 报告文件的完整对象键 |
| `content_sha256` | `TEXT` | 否 | 无 | 报告文件的 SHA-256 摘要 |
| `created_at` | `TIMESTAMPTZ` | 否 | `CURRENT_TIMESTAMP` | 记录创建时间 |

| 名称 | 类型 | 定义 |
| --- | --- | --- |
| `pk_reports` | PRIMARY KEY | `(report_id)` |
| `uq_reports_object` | UNIQUE | `(object_key)` |
| `ix_reports_created` | INDEX | `(created_at)` |

文件写入与记录提交的协作见[报告模块设计](module-report/README.md)

## 3 S3

### 3.1 使用范围与访问

报告模块使用专属桶，桶名由 [S3 配置](deployment.md#22-s3)中的 `REPORT_BUCKET` 注入
应用身份仅可读写该桶的 `reports/` 前缀，文件网关仅可读取该前缀
桶不提供匿名访问，身份交付见 [S3 部署配置](deployment.md#22-s3)

### 3.2 报告文件

| 内容 | 定义 |
| --- | --- |
| 对象键 | `reports/{report_id}/report.csv` |
| 文件格式 | UTF-8 CSV，表头为 `date,completed_count,overdue_count` |
| 数据类型 | date 为 ISO 日期，两项计数为非负整数 |
| 报告归属 | PostgreSQL 的 reports 记录，通过 object_key 引用 |
| 内容校验 | 文件摘要与 reports.content_sha256 一致 |
| 更新规则 | 报告文件不可覆盖，新报告使用新的 report_id |
| 保留规则 | 已登记的报告文件持续保留，本版本不自动清理 |

## 4 文件网关

### 4.1 接入

使用既有文件网关的链接签发能力，接口契约见[网关接入文档](../reference/file-gateway.md)
报告模块只传递已登记报告的对象键，网关用只读身份访问 S3

| 配置项 | 用途 | 来源 |
| --- | --- | --- |
| `FILE_GATEWAY_URL` | 网关端点 | [网关配置](deployment.md#23-文件网关) |
| `FILE_GATEWAY_TOKEN` | 调用身份凭据 | [网关凭据交付](deployment.md#23-文件网关) |

### 4.2 使用约束

签发链接的有效期为 15 分钟，仅允许读取指定对象
访问链接的业务授权与签发失败处理见[报告模块设计](module-report/README.md)
```

## 5 检查条件

- [ ] 总览覆盖需要构建或依赖的基础设施，每项资源对应一个详细设计 chapter
- [ ] 每项资源的依赖位置、所用能力、使用方与接入方式已定义
- [ ] 具体设计按实际内容层层深入
- [ ] 所需资源配置、数据结构与存储组织已定义，相关标识与维护归属已定义
- [ ] 如涉及生命周期、迁移或多处存储，对应规则与一致性要求已定义
- [ ] 配置与凭据来源已登记，没有实际凭据值
- [ ] 业务处理、部署操作与安全论证引用对应文档，没有重复展开
