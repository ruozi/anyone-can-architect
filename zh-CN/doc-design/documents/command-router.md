# 文档设计：command-router

## 1 文档定位

命令路由中枢的处理设计，定义输入到目标命令的路由规则、参数准备与派发过程

命令说明、注册表与共用规则归命令目录的 README
具体写法见 [readme](readme.md) 文档设计
叶子的参数治理、业务动作与回复归 [command](command.md)

## 2 文档结构

第一章写处理总流程，引用后续章节中的具体机制

第二章定义各类输入的目标命令确定规则与派发路径，引用后续具体机制

第三章起对内部机制[层层深入](../../skills/references/drill-down.md)，章节数量与标题随解决方案确定

最后两章为黑盒测试与白盒测试，均按[测试用例](../patterns/testcase.md)展开

结构示意：

```text
## 1 处理总流程
## 2 命令路由
## 3 <内部机制的一部分>
…                          章节数量随解决方案
## N 黑盒测试
## N+1 白盒测试
```

## 3 行文步骤

1. 引用命令注册表，定义输入、派发目标与路由职责边界
2. 编排处理总流程，列出需要展开的内部机制
3. 定义各类输入的目标命令确定规则、参数传递与派发路径
4. 对各内部机制[层层深入](../../skills/references/drill-down.md)，定义处理步骤、状态变化、失败分支与依赖调用
   - 依赖模块只写调用、结果与后续处理，内部设计引用对应文档
   - 叶子的业务处理与回复引用对应叶子文件
5. 在对应处理步骤下展开卡片状态，不集中汇总
   - 每个状态至少单独成为一个 [subsection](../../CONTEXT.md#subsection)，定义触发条件与处理逻辑，按[飞书卡片示意](../patterns/lark-card-mockup.md)表达
6. 根据路由契约与内部设计，分别编写黑盒测试与白盒测试
   - 两章均按[测试用例](../patterns/testcase.md)展开，指定驱动入口与观察点，引用设计依据

## 4 示例

```text
## 1 处理总流程
## 2 命令路由
### 2.1 命令直达
### 2.2 自然语言输入
## 3 输入受理与预处理
### 3.1 输入受理
#### 3.1.1 已受理
#### 3.1.2 不予受理
### 3.2 消息预处理
## 4 分类与参数提取
### 4.1 调用分类能力
### 4.2 调用参数提取能力
## 5 派发与补投
### 5.1 首次派发
### 5.2 失败与重试
#### 5.2.1 等待重试
#### 5.2.2 重试中
## 6 黑盒测试
## 7 白盒测试
```

## 5 检查条件

- [ ] 输入、派发目标与路由职责边界已定义，与命令注册表一致
- [ ] 第二章为命令路由，包含各类输入的目标命令确定规则与派发路径
- [ ] 处理总流程与各内部机制对应，内部机制已层层深入
- [ ] 依赖模块与叶子的内部设计通过引用衔接，没有重复展开
- [ ] 卡片状态随处理步骤描述，每个状态至少单独成为一个 subsection，并配飞书卡片示意
- [ ] 最后两章为黑盒测试与白盒测试，均满足[测试用例检查条件](../patterns/testcase.md#5-检查条件)
