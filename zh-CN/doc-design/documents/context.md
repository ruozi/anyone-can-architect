# 文档设计：context

## 1 文档定位

定义项目共同使用的术语及其含义
收录本业务特有、被至少两个模块共同使用且需要明确约定含义的术语
只在单个模块内部使用的术语，由该模块的设计文档定义
不收录本业务之外的内容、行业常识性术语与通用术语

项目定位归 [readme](readme.md)

## 2 文档结构

文档标题为 `# Context`
各部分使用二级标题，按下表顺序组织

| 部分 | 必要条件 | 内容与写法 |
| --- | --- | --- |
| `Language` | 始终必需 | [术语名称与定义](#21-language) |
| `Relationships` | 按需 | [概念之间的关系](#22-relationships) |
| `Example dialogue` | 按需 | [术语使用对话](#23-example-dialogue) |
| `Flagged ambiguities` | 按需 | [容易混淆的说法与明确含义](#24-flagged-ambiguities) |

### 2.1 Language

每个概念用一个三级标题建立词条
标题使用该概念的主名称，不加编号
词条标题在全文中忽略大小写后唯一
同一概念的译名与别名写在同一词条下
不同概念使用同一名称时，在名称中加入业务范围限定

主名称优先用英文
主名称采用已有代码名称或专名时，保留其原有写法
没有准确英文名称时，主名称保留原语言
英文词条标题只使用字母、数字、空格、下划线、连字符与英文句点 `.`

需要在其他语言中使用时，在标题下写固定译名，如 `中文：责任人`
译名与注解写成可见正文
定义使用团队的工作语言

定义先用一句话说明概念是什么
按需补充适用范围与容易混淆的边界
定义说明概念的含义，不只列同义词
定义中使用其他项目术语时，引用对应词条

以下说明按需写在定义后
各项使用表中的标记，不另设标题

| 标记 | 内容 |
| --- | --- |
| `别名：` | 同一概念的缩写或本业务认可的其他称呼 |
| `_Avoid_:` | 本业务应避免的称呼及原因 |
| `_对人说_:` | 面向用户的自然表达 |

设计文档使用主名称或固定译名
代码命名按编程语言的命名惯例表达同一概念
面向用户的表达保持概念含义一致

### 2.2 Relationships

需要集中说明概念之间的归属、组成或关联关系时，编写本章
关系涉及的概念链接对应词条
有方向的关系写清方向
区分概念需要明确关系的数量约束时，写清数量约束

### 2.3 Example dialogue

术语在业务交流中容易被误用时，用简短对话演示正确用法
对话中的术语引用对应词条
对话展示容易混淆的概念如何区分

### 2.4 Flagged ambiguities

某种说法容易指向不同概念时，写清它在本业务中指哪个概念
涉及的概念引用对应词条

## 3 行文步骤

1. 从业务讨论、现有文档与代码中提取候选术语
   核对使用模块及其业务用途，按[收录范围](#1-文档定位)筛选
   跨模块使用以多个模块依赖该概念的含义为依据，不只统计名称出现次数
2. 对照已有词条，识别可复用的概念、新增概念与含义变化
   已有概念复用对应词条
3. 与业务方确认新增或修订概念的主名称、定义与适用范围
4. 按 [Language](#21-language) 的规则编写或修订词条
5. 用实际业务表述检验术语的含义是否明确
   按需补充 [Relationships](#22-relationships)、[Example dialogue](#23-example-dialogue) 与 [Flagged ambiguities](#24-flagged-ambiguities)
6. 术语名称或含义变化时，更新受影响文档的用词与词条引用
   - 名称变化：同步受影响的词条锚点引用
   - 含义变化：核对相关契约与实现设计
7. 按[检查条件](#5-检查条件)审阅文档
   运行 `aca-context-check CONTEXT.md`

## 4 示例

以下以任务协作业务中的负责人和责任人为例

```markdown
# Context

## Language

### task-owner

中文：负责人
对整件任务的交付负责的人
与承担具体工作的[责任人](#owner)区分
_Avoid_: 任务责任人，容易与承担具体工作的[责任人](#owner)混淆
_对人说_: 这件事由谁负责交付

### owner

中文：责任人
承担任务中具体工作的人
_对人说_: 这项工作由谁来做
```

## 5 检查条件

- [ ] 只收录本业务特有且需要明确约定含义的术语
- [ ] 每个概念被至少两个模块共同使用，而非仅在多个位置出现名称
- [ ] 同一概念只建立一个词条
- [ ] 名称与定义能区分容易混淆的概念
- [ ] 附加说明符合 [Language](#21-language) 的规定
- [ ] 文档与代码中的术语含义与词条定义一致
- [ ] [关系](#22-relationships)、[对话](#23-example-dialogue)与[消歧](#24-flagged-ambiguities)符合各自的编写条件与表达规则
- [ ] 术语名称或含义变化已同步到受影响文档
- [ ] 词条引用有效
- [ ] `aca-context-check` 检查通过
