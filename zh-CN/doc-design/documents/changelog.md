# 文档设计：changelog

## 1 文档定位

按版本记录对使用者有意义的变化

## 2 文档结构

结构遵循 [Keep a Changelog](../../SSOT.md#8-版本)
未发布区块置于顶部
已发布版本按发布日期倒序排列

```text
# Changelog
## [未发布]
### <变更类别>
## [<版本号>] — <YYYY-MM-DD>
### <变更类别>
```

变更类别使用新增、变更、弃用、移除、修复与安全
只写有变更条目的类别
每条说明使用者可感知的变化
有兼容影响时，说明影响范围
需要迁移时，说明迁移操作
版本号、发布日期与实际发布记录一致

## 3 行文步骤

1. 从实际完成的改动中筛选对使用者有意义的变化
2. 将同一变更涉及的多次提交归纳为一个条目
   按变更类别写入未发布区块
3. 核对本次变更对契约、配置与使用方式的影响
   按[文档结构](#2-文档结构)的规则补充兼容影响与迁移说明
4. 发布时，将本次实际交付的条目归入对应版本区块
   在顶部保留未发布区块
5. 核对已发布版本的变更记录与实际交付一致
   已发布记录有误时，按该版本的实际交付纠正

## 4 示例

结构示例见 [CHANGELOG 模板](../../templates/CHANGELOG.md.example)

## 5 检查条件

- [ ] 条目描述实际完成且对使用者有意义的变化
- [ ] 未发布区块与已发布版本区块符合[文档结构](#2-文档结构)的组织与排序规则
- [ ] 变更类别符合[文档结构](#2-文档结构)的规定
- [ ] 版本号和发布日期与实际发布记录一致
- [ ] 兼容影响与迁移说明符合[文档结构](#2-文档结构)的规定
- [ ] 已发布记录与该版本的实际交付一致
