# 文档设计：command

## 1 文档定位

单个叶子命令的处理设计，定义参数解析与校验、业务处理与交互结果

命令注册与共用交互约定归命令目录的 README
具体写法见 [readme](readme.md) 文档设计
输入到目标命令的路由、参数准备与派发归 [command-router](command-router.md)
承接业务的模块内部实现与测试归对应模块文档

## 2 文档结构

第一章写处理总流程，引用后续章节中的具体机制

第二章定义参数来源、解析规则、校验条件与失败处理，无参命令注明无参数

第三章起对业务处理与内部机制[层层深入](../../skills/references/drill-down.md)，章节数量与标题随解决方案确定

最后两章为黑盒测试与白盒测试，均按[测试用例](../patterns/testcase.md)展开

结构示意：

```text
## 1 处理总流程
## 2 参数解析与校验
## 3 <业务处理或内部机制的一部分>
…                          章节数量随解决方案
## N 黑盒测试
## N+1 白盒测试
```

## 3 行文步骤

1. 引用命令注册表，标注叶子键，定义参数、业务依赖与交互结果
2. 编排处理总流程，列出需要展开的业务处理与内部机制
3. 定义参数来源、解析规则、校验条件与失败处理，已有契约通过引用衔接
   - 无参命令注明无参数
4. 对业务处理与内部机制[层层深入](../../skills/references/drill-down.md)，定义步骤、结果分支与依赖调用
   - 依赖模块只写调用、结果与后续处理，内部设计引用对应文档
   - 涉及重复执行、异步处理或通知时，定义对应规则与边界
5. 在对应步骤下展开卡片状态与操作，不集中汇总
   - 每个状态至少单独成为一个 [subsection](../../CONTEXT.md#subsection)，定义触发条件与处理逻辑，按[飞书卡片示意](../patterns/lark-card-mockup.md)表达
   - 操作定义触发条件、权限、参数及目标
6. 根据交互契约与内部设计，分别编写黑盒测试与白盒测试
   - 两章均按[测试用例](../patterns/testcase.md)展开，指定驱动入口与观察点，引用设计依据
   - 业务模块的内部测试引用对应模块测试文档，不重复展开

## 4 示例

```text
## 1 处理总流程
## 2 参数解析与校验
### 2.1 参数 Schema
### 2.2 参数解析
### 2.3 参数校验
#### 2.3.1 缺少任务名称
#### 2.3.2 参数格式错误
## 3 新建任务
### 3.1 调用任务模块
### 3.2 结果处理
#### 3.2.1 创建成功
#### 3.2.2 业务拒绝
#### 3.2.3 系统失败
## 4 黑盒测试
## 5 白盒测试
```

## 5 检查条件

- [ ] 叶子键与命令注册表一致，参数、业务依赖与交互结果已定义
- [ ] 第二章为参数解析与校验，包含来源、解析规则、校验条件与失败处理，无参命令注明无参数
- [ ] 总流程与业务处理、内部机制对应，具体机制已层层深入
- [ ] 依赖模块的内部实现与测试通过引用衔接，没有重复展开
- [ ] 涉及重复执行、异步处理或通知时，对应规则与边界已定义
- [ ] 卡片状态随步骤描述，每个状态至少单独成为一个 subsection，并配飞书卡片示意
- [ ] 操作包含触发条件、权限、参数及目标
- [ ] 最后两章为黑盒测试与白盒测试，均满足[测试用例检查条件](../patterns/testcase.md#5-检查条件)
