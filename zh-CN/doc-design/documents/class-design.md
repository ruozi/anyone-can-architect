# 文档设计：class-design

## 1 文档定位

一个模块内部的解决方案设计
负责指导模块内部的全部实现细节的无歧义实现
其中必须包含 interface 定义的每个对外能力怎样实现

模块对外的能力定义归 [interface](interface.md)
对外契约的黑盒测试归 [testcase](testcase.md)
内部机制的白盒测试写在本文最后一章，按[测试用例](../patterns/testcase.md)展开
顶层模块之间怎样协作归 [architecture](architecture.md)
有子模块时，本文定义内部组成与子模块协作，子模块的实现归其自身的 class-design，分工见 [module 文档组](../document-sets/module.md#23-父子职责)

## 2 文档结构

正文依次为「内部机制」「对外能力」与「内部测试」
「内部机制」由「内部组成」与公共机制构成

「内部机制」的第一个 [chapter](../../CONTEXT.md#chapter) 为「内部组成」
- 列出本模块的类或组件、本模块拥有的数据与依赖的下游模块或外部系统
- 有子模块时，按以下规则组织本层与直接子模块
  - 组成图将每个直接子模块作为一个整体节点，表达本模块结构、直接子模块及它们之间的调用与反馈关系
  - 不绘制子模块内部的类、状态、算法与更深层子模块
  - 以模块表列出直接子模块、能力与责任边界，子模块名链接对应 README，能力链接子级 interface

「内部组成」之后为公共机制，每个公共机制一个 [chapter](../../CONTEXT.md#chapter)，没有公共机制时不设
公共机制须同时满足以下条件
- 至少被两个「对外能力」使用
- 定义这些能力共享的规则、状态或保证

单个字段、字段集合或通知辅助方法不构成公共机制，写在使用它的实现旁

「对外能力」的 [chapter](../../CONTEXT.md#chapter) 与 [section](../../CONTEXT.md#section) 与 interface 一一对应，排在「内部机制」之后，对每个 [section](../../CONTEXT.md#section) [层层深入](../../CONTEXT.md#drill-down)
最后一章为「内部测试」，根据本文定义的内部结构与处理机制设计白盒测试
整章按[测试用例](../patterns/testcase.md) pattern 展开，依次写夹具、测试场景与测试用例

结构示意：

```text
「内部机制」
## 1 内部组成              类或组件、拥有的数据与依赖 · 有子模块时含直接子模块表
## 2 <公共机制>            按需，满足公共机制条件才设
…
「对外能力」
## N-1 <一类业务>          对应 interface 的一个 chapter
### N-1.1 <接口>           对应 interface 的一个 section · 对它层层深入
#### N-1.1.1 <细分>        按需
## N <接口>                interface 里 chapter 本身是接口时同样 · 对它层层深入
## N+1 内部测试            按测试用例 pattern 展开，内容降一层标题
```

## 3 行文步骤

行文顺序与阅读顺序不同：先逐个写完对外能力的实现，再从中提炼公共机制

1. 理解所有 interface 定义的对外能力，以及实现它们要什么、依赖哪些下游模块或外部系统
2. 起草「内部组成」
   - 列出实现对外能力所需的类或组件、本模块拥有的数据与依赖
   - 有子模块时，子模块的能力链接子级 interface，不复述其签名与实现
   - 只定义本模块拥有的数据结构
3. 对每个「对外能力」依次[层层深入](../../CONTEXT.md#drill-down)：每个对应 interface 的 [chapter](../../CONTEXT.md#chapter) 或 [section](../../CONTEXT.md#section)，写这个接口怎样实现
   - 在一处写完整的执行过程：输入、转换、调用、分支与输出
   - 只服务于这个接口的字段、转换与分支写在对应实现旁
   - 对外结果只用 interface 已声明的结果，内部错误到它们的映射写清
   - interface 已定义的类型、结果与错误语义只链接不复述
   - 实现代码可以带方法签名，表达输入参数怎样传到下游
   - 与依赖模块或外部系统的交互只写本模块发出的调用和收到的结果，不描述对方内部
   - 厂商或平台的实现细节归其自身的 Adapter
   - 按[表达方式](#31-表达方式)选择表达，按[完整性依据](#32-完整性依据)确定分支
4. 提炼公共机制
   - 从已写完的实现中找出被多个对外能力共用的规则、状态或保证
   - 满足[公共机制条件](#2-文档结构)的，移入独立的 [chapter](../../CONTEXT.md#chapter)
   - 各使用处保留执行顺序：调用机制的位置、传入的输入、得到的结果与后续分支
   - 机制内部的规则与实现细节只在机制章说明，使用处引用
   - 明确机制的正向流程、固有的失败分支、保证、边界条件与阈值，验证场景写在测试部分
   - 不满足条件的，留在使用它的实现旁
5. 排定阅读顺序
   - 「内部组成」在前，公共机制随后，「对外能力」再后，最后为「内部测试」
   - 「对外能力」的 [section](../../CONTEXT.md#section) 顺序与 interface 一致
   - 通篇核对 [chapter](../../CONTEXT.md#chapter) 编号连续
6. 写「内部测试」
   - 从内部结构与处理机制列出待验证的分支、状态转移、错误映射与不变量
   - 按[测试用例](../patterns/testcase.md) pattern 定义夹具、列出场景并展开用例，设计依据链接本文对应设计位置
   - 明确测试的驱动入口与观察点，按需使用内部入口、状态与依赖替身
   - 对外契约已经定义的黑盒场景引用 testcase，不重复展开
   - 有子模块时，验证子模块之间的组合与协作，子模块自身的契约与实现由子级文档验证

### 3.1 表达方式

| 内容 | 表达 |
| --- | --- |
| 简单调用与字段转换 | 代码 |
| 无循环的多步骤处理 | 编号列表<br>每步以加粗短语开头，表达这一步的目的<br>具体操作与条件分支缩进在该步下 |
| 有循环，或分支走向需要整体呈现的流程 | [流程图](../patterns/flowchart.md) |
| 跨对象的交互时序 | [时序图](../patterns/sequence-diagram.md) |
| 允许的状态变化 | [状态机](../patterns/state-machine.md)，不代替处理方法的执行顺序 |

图或代码已经表达的信息，不再用文字复述
一行代码能完整表达的调用，不追加解释段落

代码按以下粒度展示
- 简短的处理方法直接展示必要的处理、字段转换与通知
- 多处重复的接线写一段代表性代码
- 代表性代码标明它代表哪些位置
- 这些位置的共同约束只写一次
- 代表性代码不省略关键决定
- 代表性代码不冒充完整实现

### 3.2 完整性依据

分支以真实契约与已确认需求为依据
- 区分参数校验、调用异常、厂商业务结果与未知状态
- 契约没有提供的结果，不为其设计重试、状态机或通知
- 尚未核实的行为标为待核实，不假定其成立或不成立

示例：厂商 setter 返回 `void`
- 契约不提供业务结果时，不设计设置成功或失败的流程
- 调用异常未核实时，标为待核实

## 5 检查条件

- [ ] 第一章为「内部组成」，有子模块时只展开本层与直接子模块，与直接子模块目录一致，子模块的能力只链接子级 interface
- [ ] 每个公共机制章都满足公共机制条件，能列出至少两个使用它的对外能力
- [ ] 「对外能力」的 [chapter](../../CONTEXT.md#chapter) 与 [section](../../CONTEXT.md#section) 与 interface 一一对应，排在「内部机制」之后，编号连续
- [ ] 「内部机制」与每个「对外能力」都层层深入到叶子，模块的实现只有一种
- [ ] 每个接口的执行顺序在一处能读懂，不需要跨章节拼接
- [ ] 示例的输入、关键转换与输出连贯
- [ ] 没有复述 interface 定义的类型、结果与错误语义
- [ ] 文字、图与代码之间没有重复表达
- [ ] 公共机制的保证、边界条件与阈值明确，验证场景集中在测试部分
- [ ] 最后一章为「内部测试」，根据内部设计验证分支、状态转移、错误映射与不变量，满足测试用例 pattern
- [ ] 对外结果都是 interface 已声明的，内部错误到它们的映射写清了
- [ ] 每个分支都有契约或已确认需求作为依据，尚未核实的行为已标为待核实
- [ ] 只定义本模块拥有的数据结构
- [ ] 与依赖模块或外部系统的交互只有本模块发出的调用和收到的结果
- [ ] 厂商或平台的实现细节没有上移到本模块
- [ ] 「对外能力」没有复述公共机制已说明的内容
