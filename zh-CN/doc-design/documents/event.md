# 文档设计：event

## 1 文档定位

单个后台事件或定时任务的处理设计，定义参数解析与校验、业务处理与输出结果

事件注册表与共用触发策略归事件目录的 README
具体写法见 [readme](readme.md) 文档设计
触发受理、目标事件确定与转发归 [event-mediator](event-mediator.md)
承接业务的模块内部实现与测试归对应模块文档

## 2 文档结构

第一章写处理总流程，引用后续章节中的具体机制

第二章定义参数来源、解析规则、校验条件与失败处理，无参事件注明无参数

第三章起对业务处理与内部机制[层层深入](../../skills/references/drill-down.md)，章节数量与标题随解决方案确定

最后两章为黑盒测试与白盒测试，均按[测试用例](../patterns/testcase.md)展开

结构示意：

```text
## 1 处理总流程
## 2 参数解析与校验
## 3 <业务处理或内部机制的一部分>
…                          章节数量随解决方案
## N 黑盒测试
## N+1 白盒测试
```

## 3 行文步骤

1. 引用事件注册表与共用触发策略，标注事件键，定义输入上下文、业务依赖与输出结果
2. 编排处理总流程，列出需要展开的业务处理与内部机制
3. 定义参数来源、解析规则、校验条件与失败处理，已有契约通过引用衔接
   - 无参事件注明无参数
4. 对业务处理与内部机制[层层深入](../../skills/references/drill-down.md)，定义步骤、结果分支与依赖调用
   - 依赖模块只写调用、结果与后续处理，内部设计引用对应文档
   - 涉及重复执行、重试、放弃或通知时，定义对应规则与边界
   - 对外输出定义条件、内容与目的地，无输出时注明完成条件
5. 如有卡片，在对应步骤下展开卡片状态，不集中汇总
   - 每个状态至少单独成为一个 [subsection](../../CONTEXT.md#subsection)，定义触发条件与处理逻辑，按[飞书卡片示意](../patterns/lark-card-mockup.md)表达
   - 如有操作，定义触发条件、权限、参数及目标
6. 根据事件契约与内部设计，分别编写黑盒测试与白盒测试
   - 两章均按[测试用例](../patterns/testcase.md)展开，指定驱动入口与观察点，引用设计依据
   - 业务模块的内部测试引用对应模块测试文档，不重复展开

## 4 示例

```text
## 1 处理总流程
## 2 参数解析与校验
### 2.1 报告周期与接收对象
### 2.2 参数解析
### 2.3 参数校验
## 3 周报生成
### 3.1 查询业务数据
### 3.2 生成报告内容
## 4 周报发送
### 4.1 发送条件与目的地
### 4.2 发送结果处理
#### 4.2.1 发送成功
#### 4.2.2 发送失败
### 4.3 重试与放弃
## 5 黑盒测试
## 6 白盒测试
```

## 5 检查条件

- [ ] 事件键与注册表一致，输入上下文、业务依赖与输出结果已定义
- [ ] 第二章为参数解析与校验，包含来源、解析规则、校验条件与失败处理，无参事件注明无参数
- [ ] 总流程与业务处理、内部机制对应，具体机制已层层深入
- [ ] 依赖模块的内部实现与测试通过引用衔接，没有重复展开
- [ ] 涉及重复执行、重试、放弃或通知时，对应规则与边界已定义
- [ ] 对外输出包含条件、内容与目的地，无输出时注明完成条件
- [ ] 如有卡片，状态随步骤描述，每个状态至少单独成为一个 subsection，并配飞书卡片示意
- [ ] 如有操作，包含触发条件、权限、参数及目标
- [ ] 最后两章为黑盒测试与白盒测试，均满足[测试用例检查条件](../patterns/testcase.md#5-检查条件)
