# 文档设计：user-manual

## 1 文档定位

从用户视角，指导产品配置、场景使用与问题处理
用户无需阅读内部设计文档就能完成手册所支持的场景

用户操作与界面依据 [interaction](interaction.md)
访问入口、制品取得与更新方式依据项目选用的 [distribution](distribution.md) 或 [deployment](deployment.md)

## 2 文档结构

开头交代适用用户、平台与版本范围

第一章说明使用所需的环境与访问或启动方式，按需说明安装、登录和配置步骤
从第二章起，按用户使用场景分章
各场景按[层层深入](../../skills/references/drill-down.md)展开
每个场景说明适用条件、操作步骤、完成结果与失败后的处理

使用内容之后设置“调试与验证”章节，说明整体使用的检查方式与异常定位方法
按需设置“FAQ”章节，说明常见问题的适用条件、处理方法与反馈方式

结构示意：

```text
## 1 环境与配置
## 2 <使用场景>
### 2.1 <具体内容>
#### 2.1.1 <具体内容>
### 2.2 <具体内容>
## 3 <使用场景>
…
## N 调试与验证
## N+1 FAQ              按需
```

## 3 行文步骤

1. 确定用户、适用范围与手册支持的使用场景
   - 按用户目标组织场景，确认所需权限、输入与操作条件
2. 编写环境与配置
   - 说明使用环境与访问或启动方式，按实际操作顺序描述所需的制品取得、安装、登录与配置，并提供完成后的确认方式
   - 配置项说明用途、取值来源与完成后的确认方式
3. 展开各使用场景
   - 按实际操作顺序描述输入、操作步骤、完成结果与失败后的处理
   - 菜单、按钮、提示与术语使用产品实际文案
   - 操作位置或结果难以用文字定位时提供截图
4. 补充调试与验证，以及所需 FAQ
   - 定义整体使用的检查步骤与通过条件
   - 提供用户能执行的定位与恢复操作，使用场景引用对应内容
   - 反馈说明联系渠道与需附的版本、错误、日志或截图，不要求提供实际凭据值
5. 核对实际产品
   - 访问或启动方式、所需配置、操作与结果符合手册适用的产品版本
   - 使用所需信息在手册或面向用户的资料中可取得，不依赖内部设计文档

## 4 示例

````markdown
# 部门报告工具使用手册

面向使用 Windows 桌面版 2.0 的部门负责人，支持生成、导出与查看部门报告

## 1 环境与配置

1. 从公司软件中心取得「部门报告工具」，完成安装
2. 打开工具，使用公司账号登录
   - 看到所属部门表示登录成功
   - 未显示所属部门时，联系管理员登记部门权限，不继续生成报告
3. 在「设置」中选择导出目录，再点击「检查目录」
   - 显示「目录可写」后保存设置
   - 目录不可写时，改为本人有写入权限的目录后重新检查

## 2 生成并导出部门报告

### 2.1 确定报告范围

#### 2.1.1 选择部门

在「部门报告」中选择需要查看的部门
列表只显示当前账号有权限的部门
目标部门不在列表中时，联系管理员申请权限

#### 2.1.2 选择日期

选择开始日期与结束日期，点击「预览范围」
例如选择 2026-09-01 至 2026-09-30，预览显示「2026 年 9 月」及对应部门
范围错误时修改日期，不继续生成

### 2.2 生成与核对

1. 点击「生成报告」，等待状态变为「已生成」
   - 显示失败时查看错误提示，按 [§4](#4-调试与验证)排查，不反复点击
2. 核对报告页顶部的部门、日期范围与记录数
   - 部门或日期不符时重新选择范围
   - 记录数为 0 时查看「无数据说明」，确认该部门在所选范围内是否有业务记录

### 2.3 导出报告

1. 点击「导出 CSV」，确认保存目录与文件名
2. 显示「导出完成」后点击「打开目录」
3. 打开导出的 CSV，核对部门、日期与记录数
   - 文件被其他程序占用时关闭该程序，再重新导出
   - 文件缺失或内容不符时，按 [§4](#4-调试与验证)检查并反馈

## 3 查看已有报告

1. 打开「历史报告」，按部门与日期查找报告
2. 点击报告记录，查看部门、日期与生成时间
3. 需要导出时点击「导出 CSV」，按 [§2.3](#23-导出报告)核对文件

历史报告保持生成时的数据，不随业务数据变化自动更新
需要最新结果时，按 [§2](#2-生成并导出部门报告)重新生成报告

## 4 调试与验证

| 检查动作 | 预期结果 | 异常处理 |
| --- | --- | --- |
| 查看账号与部门 | 当前账号和目标部门正确 | 重新登录，缺少部门权限时联系管理员 |
| 检查导出目录 | 显示「目录可写」 | 更换目录后重新检查 |
| 核对报告与 CSV | 部门、日期范围和记录数一致 | 保留报告编号，联系管理员核查 |

在「帮助 → 导出诊断记录」保存本次问题的诊断文件
反馈给管理员时附工具版本、报告编号、发生时间、错误提示与诊断文件
不要附密码或登录凭据

## 5 FAQ

**提示「目录不可写」怎么办？**

在「设置」中选择本人有写入权限的目录，点击「检查目录」并保存

**业务记录更新后，历史报告为什么没有变化？**

历史报告保留生成时的数据，需要最新结果时重新生成

**误关窗口后是否需要重新生成？**

先到「历史报告」查找已生成记录，找到后可以继续查看或导出
未生成成功的报告需要重新生成
````

## 5 检查条件

- [ ] 适用用户、平台、版本范围与支持的场景已交代
- [ ] 场景按用户目标组织，复杂内容的拆解能够支撑完整操作
- [ ] 使用环境与访问或启动方式已说明，所需的安装、登录与配置按实际顺序组织，配置来源与确认方式已定义
- [ ] 适用条件、输入、操作步骤、完成结果与失败后的处理已交代
- [ ] 术语、菜单、按钮与提示符合实际产品文案
- [ ] 用户能定位所述操作，必要时有截图辅助，无需理解内部实现
- [ ] 整体验证有可执行动作与可观察结果，问题有定位、恢复或反馈方式
- [ ] 手册与实际产品版本一致，不依赖内部设计文档
- [ ] 反馈所需信息可由用户取得，没有要求提供实际凭据值
