# 文档设计：deployment

## 1 文档定位

定义已固化版本在目标环境中的部署、运行验证与故障处置流程，包括失败恢复与版本退回方式

## 2 文档结构

第一章定义部署前提，包括版本与制品、目标环境、部署单元、配置与凭据来源及依赖条件
资源结构与权限引用 [infrastructure](infrastructure.md)，防护依据引用 [security](security.md)

第二章按本项目的实际顺序展开部署流程
每步定义执行方式、通过条件、失败处理与恢复位置
环境准备、依赖开通与检查按实际执行顺序归入流程

第三章定义运行验证与故障处置，包括业务可用性检查、日常查看、恢复、版本退回与清理
定义整体验证标准，由相关部署与处置步骤引用
定义版本、配置与持久数据的退回边界，不能退回时定义替代处置方式

各章按实际内容[层层深入](../../skills/references/drill-down.md)，不固定运行环境或小节模板

结构示意：

```text
## 1 部署前提
## 2 部署流程
### 2.1 <执行阶段>
### 2.2 <执行阶段>
…
## 3 运行验证与故障处置
### 3.1 <验证或处置内容>
### 3.2 <验证或处置内容>
…
```

## 3 行文步骤

1. 确定部署前提
   - 定义 release 锁定的版本来源、制品取得方式及源码提交与制品身份的对应关系
   - 定义目标环境、部署单元、允许的版本组合及所需权限、配置、凭据与依赖
   - 区分首次部署与后续更新的前置条件
2. 设计部署流程
   - 按依赖关系安排制品取得、环境准备、依赖检查、数据迁移、启动与切换等操作
   - 为每一步定义执行方式、通过条件、失败处理与恢复位置
   - 定义配置与凭据的交付方式、缺失行为及运行所需的访问权限
   - 定义并发部署、重载与退回之间的协调方式
   - 涉及停机或切换时，定义正在处理的请求、任务与连接如何处置
3. 定义运行验证
   - 定义版本、进程、依赖与业务能力的检查动作、通过条件与失败表现
   - 按实际需要定义检查的超时、重试与失败后能否继续
   - 定义部署完成与故障恢复后的整体验证标准
4. 定义故障处置与后续维护
   - 按故障场景定义查看状态、日志与依赖的方式，以及恢复操作与结果验证
   - 定义版本、配置与持久数据的兼容关系，确定退回条件、操作顺序与失败处理
   - 无法退回时，定义恢复数据、修复当前版本或其他适用的处置流程
   - 定义制品、备份、日志与业务数据的保留和清理范围，引用相关资源约束
5. 按 [§2](#2-文档结构)组织各章，核对完整流程
   - 制品能够追溯到已固化版本，环境与依赖条件满足执行要求
   - 各步骤的结果满足后续前提，失败恢复与退回操作不冲突
   - 资源结构与权限引用 [infrastructure](infrastructure.md)，防护依据引用 [security](security.md)

## 4 示例

````markdown
# 报告服务部署

## 1 部署前提

| 内容 | 定义 |
| --- | --- |
| 目标环境 | Linux 服务器，容器运行服务，网关转发业务请求 |
| 部署单元 | 报告服务，一个实例对外接收请求 |
| 版本来源 | release 锁定的 v2.0.0 |
| 制品来源 | 内部镜像仓库，镜像身份与源码提交记录在 release-manifest.json |
| 当前版本 | v1.9.0，保留对应镜像、配置与部署记录 |
| 状态目录 | /srv/report-service，记录当前版本、镜像摘要与上一成功版本 |
| 依赖 | PostgreSQL 与对象存储，资源设计见[infrastructure](infrastructure.md) |
| 配置与凭据 | 配置文件与只读凭据文件，交付权限见[部署身份 §3](security.md#3-部署身份) |

部署账号能够拉取镜像、管理本服务容器、执行迁移及切换网关
部署、重载与退回由部署脚本取得本服务的独占锁，冲突时拒绝执行
首次部署先创建状态目录、依赖资源与服务身份，再执行部署流程
本例更新已有服务，当前版本保持运行直到新版本验证通过

`scripts/deploy-report.sh` 提供身份校验、环境准备、候选启动、切换、验证、退回与清理操作
各操作返回非零退出码表示失败，记录操作阶段，不在失败时自动推进

## 2 部署流程

### 2.1 取得并校验制品

**执行**：运行 `bash scripts/deploy-report.sh prepare v2.0.0`，取得 Tag、发布清单与对应镜像

**通过**：Tag 已固化，清单中的源码提交等于 Tag 指向，拉取镜像的摘要等于清单记录

**失败与恢复**：停止部署，当前版本继续运行
修复制品来源或权限后重试本阶段，不重新构建替换同一身份的镜像

### 2.2 检查运行条件

**执行**：运行 `bash scripts/deploy-report.sh preflight v2.0.0`

**通过**：配置与凭据齐全，数据库身份正确且具备所需权限，对象存储可完成临时对象写入、读取与删除
状态目录可写，候选服务端口可用，部署锁可取得

**失败与恢复**：停止部署，不修改当前版本
修正对应条件后重试，检查产生的临时对象须先清理

### 2.3 执行数据迁移

**执行**：运行 `bash scripts/deploy-report.sh migrate v2.0.0`

**通过**：迁移记录标记本次迁移成功，reports 表新增可空的 source_digest 字段
本次变更不删除或改变旧字段，v1.9.0 仍可读取与写入
迁移顺序与事务边界见[数据库迁移 §2.3](infrastructure.md#23-数据库迁移)

**失败与恢复**：不启动候选版本，按迁移记录确定已完成的操作
本次迁移在单个事务中执行，失败回滚后修正问题，再执行未完成的迁移
已成功的迁移不重复执行

### 2.4 启动并验证候选版本

**执行**：运行 `bash scripts/deploy-report.sh start-candidate v2.0.0`，使用独立端口启动候选容器，再执行 §3.1 的验证

**通过**：候选版本全部验证通过，验证数据已清理

**失败与恢复**：停止候选容器，保留日志，旧版本继续接收请求
修正配置后重试本阶段，代码需要修复时使用新的固化版本从 §2.1 开始

### 2.5 切换并确认运行

**执行**：运行 `bash scripts/deploy-report.sh activate v2.0.0`，将网关新请求切到候选版本，再经网关执行 §3.1 的验证
旧版本不再接收新请求，等待已有请求完成，最长 60 秒
本服务不执行独立后台任务

**通过**：新版本验证通过，旧请求处理完毕，状态记录更新为当前 v2.0.0、上一成功版本 v1.9.0

**失败与恢复**：验证失败时执行 §3.2，旧请求未完成时保留旧容器并报告，不执行清理
恢复执行前检查网关实际指向与状态记录，不重复切换

## 3 运行验证与故障处置

### 3.1 运行验证

运行 `bash scripts/deploy-report.sh verify v2.0.0`
每项检查超时 10 秒，失败即停止，不自动重试

| 检查 | 通过条件 |
| --- | --- |
| 版本身份 | 服务报告的源码提交与 v2.0.0 一致 |
| 数据库 | 能以应用身份读写验证记录 |
| 报告业务 | 使用专用验证账号生成并下载报告，内容符合请求 |
| 数据清理 | 本次验证记录与对象均已删除 |

### 3.2 新版本验证失败

1. 执行 `bash scripts/deploy-report.sh rollback`，核对上一成功版本的镜像与配置仍可用
2. 将网关新请求切回 v1.9.0，保留新版本容器与日志用于排查
3. 按 §3.1 的标准验证旧版本，版本身份改为 v1.9.0
4. 验证通过后记录当前版本为 v1.9.0，再停止新版本容器

本次退回保留已成功的数据迁移，不回退数据库结构或删除新版本写入的业务记录
旧版本验证失败时保留现场并告警，按数据库与对象存储故障定位，不反复切换版本
业务数据异常时按[数据恢复 §2.4](infrastructure.md#24-数据恢复)处置，禁止用旧备份直接覆盖现有业务数据

### 3.3 查看与清理

`bash scripts/deploy-report.sh status` 显示网关指向、运行版本、部署阶段与上一成功版本
`bash scripts/deploy-report.sh logs` 读取本服务容器日志，不输出凭据

部署验证通过且旧请求处理完毕后，清理旧容器与本次验证数据
保留当前及上一成功版本的镜像、配置和部署记录
数据库、报告对象及其他项目资源不在部署清理范围内
````

## 5 检查条件

- [ ] 版本来自 release 固化的 Tag，制品身份能够追溯到对应源码提交
- [ ] 目标环境、部署单元、版本组合、配置、凭据与依赖条件已定义
- [ ] 首次部署与后续更新的前置条件已区分
- [ ] 部署流程覆盖全部必要操作，每步有执行方式、通过条件、失败处理与恢复位置
- [ ] 配置与凭据的交付、访问权限及缺失行为已定义
- [ ] 并发部署、重载与退回的协调方式，以及切换期间请求、任务和连接的处理已定义
- [ ] 整体验证覆盖版本身份、运行状态、依赖与业务可用性
- [ ] 版本、配置与持久数据的退回条件、兼容边界及无法退回时的处置已定义
- [ ] 故障定位、恢复与退回流程有结果验证，恢复执行与实际运行状态一致
- [ ] 制品、备份、日志与业务数据的保留和清理范围已定义
- [ ] 资源设计与防护依据引用对应文档，没有实际凭据值
