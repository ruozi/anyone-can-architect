# 文档设计：readme

## 1 文档定位

当前层级的文档入口，介绍这一层的职责，主要提供下一层文档导航
按需承载共用机制与注册表，供对应设计文档引用

## 2 文档结构

| 内容 | 要求 |
| --- | --- |
| 定位 | 介绍当前层级的职责 |
| 文档导航 | 链接下一层文档并标注用途，按需分组或提供阅读顺序 |
| 公共内容 | 按需设置共用机制、注册表等章节，供相关文档引用 |

结构示意：

```text
<定位>
<文档导航>
## <公共内容>             按需设置，章节随内容确定
```

## 3 行文步骤

1. 确定内容与职责
   - 列出所在层级的所有设计文档，判断是否需要共用机制、注册表或其他公共内容
   - 如有对应工程类型或文档组，按其规定确定文档组成
   - 根 README 可以只链接文档入口，其余文档由文档入口导航
   - CONTEXT 与 SSOT 能从文档入口到达时，根 README 不单独列出
2. 组织文档结构
   - 编写定位，介绍当前层级的职责
   - 导航按文档职责分组，公共内容按机制或注册对象分章，内容单一时无需额外分组
   - 根 README 可加标语、徽章与快速开始，文档入口可以用带链接的徽章承载
   - 根 README 可写一行版本状态，选用 ROADMAP 时链接对应详情
3. 编写导航
   - 用表格链接直接下一层的文档或目录 README，每个入口一行，附一句用途
   - 同一导航项不重复列出
   - 按需提供阅读顺序，依据读者任务串联相关文档
4. 展开公共内容
   - 共用机制按职责分章，对各机制[层层深入](../../skills/references/drill-down.md)，相关文档引用对应规则
   - 单个对象的处理机制归对应设计文档
   - 根据注册表用途定义字段含义与取值规则
   - 每个注册对象一行，包含对象标识与对应设计入口
   - 共用策略通过引用衔接，不在每行重复定义
5. 核对一致性
   - 检查导航覆盖与链接有效性，文档增删改名时同步链接
   - 检查注册表与设计文档的对象、标识及入口一致
   - 检查共用内容是否重复定义

## 4 示例

```markdown
# 业务事件

组织逾期提醒与周报的后台触发及处理

| 文档 | 用途 |
| --- | --- |
| [事件调度](00-mediator.md) | 触发受理与事件转发 |
| [逾期提醒](01-overdue.md) | 提醒负责人处理逾期事项 |
| [周报](02-weekly-report.md) | 生成并发送本周业务报告 |

## 1 共用触发机制

### 1.1 每周触发

每周五 18:00（北京时间）触发，报告周期为本周一至触发时点
错过触发时点后补发当周报告，进入下一周后不再补发上一周报告

### 1.2 每日触发

每天 09:00（北京时间）触发
错过触发时点后按当前状态重算，进入次日后不再补发前一日提醒

## 2 事件注册表

事件键唯一标识事件，触发策略引用前面的共用触发机制

| 事件键 | 名称 | 职责 | 触发策略 | 设计入口 |
| --- | --- | --- | --- | --- |
| event.overdue | 逾期提醒 | 提醒负责人处理逾期事项 | [每日触发](#12-每日触发) | [逾期提醒](01-overdue.md) |
| event.weekly_report | 周报 | 汇总本周业务进展并发送报告 | [每周触发](#11-每周触发) | [周报](02-weekly-report.md) |
```

## 5 检查条件

- [ ] 定位介绍当前层级的职责
- [ ] 文档导航覆盖直接下一层，每个入口包含链接与一句用途，同一导航项不重复列出
- [ ] 根 README 只链接文档入口时，其余文档都能从文档入口到达
- [ ] 如有阅读顺序，按读者任务组织
- [ ] 如有共用机制，已层层深入，相关文档引用对应规则，没有重复定义
- [ ] 如有注册表，每个对象一行，包含对象标识与设计入口，字段含义与取值规则已定义
- [ ] 如有注册表，与对应设计文档一致，共用策略通过引用衔接
- [ ] 链接指向真实文件与章节，没有占位链接
- [ ] 如有版本状态，详情链接对应版本记录
