# 文档设计：roadmap

## 1 文档定位

记录项目的版本目标与推进状态

## 2 文档结构

各部分使用二级标题，按下表顺序组织

| 部分 | 必要条件 | 内容与写法 |
| --- | --- | --- |
| 当前状态 | 始终必需 | [当前版本与推进阶段](#21-当前状态) |
| 后续版本规划 | 已确认后续版本计划 | [各计划版本的目标与范围](#22-后续版本规划) |
| 版本演进路径 | 需要集中展示多个版本的目标与状态 | [各版本的目标与状态](#23-版本演进路径) |
| 方向规划 | 存在尚未落实到具体版本的方向 | [尚未细化为版本范围的方向](#24-方向规划) |

### 2.1 当前状态

有已发布版本时，写明最新发布版本
有正在推进的版本时，写明目标版本与所处阶段
记录已达到的里程碑

### 2.2 后续版本规划

每个计划版本一个 [section](../../CONTEXT.md#section)，标题使用目标版本号
先说明该版本要达成的结果
再列出已确认纳入该版本的功能、修复或调整
容易被误认为纳入该版本的内容，明确列为不纳入项并说明原因

### 2.3 版本演进路径

用表格汇总各版本的版本号、目标与状态

### 2.4 方向规划

按方向分别说明希望达成的结果

## 3 行文步骤

1. 核对已发布版本与当前实际进展，按[当前状态](#21-当前状态)的规则记录
2. 与开发者确认后续版本的目标与范围
   按[后续版本规划](#22-后续版本规划)的规则记录
3. 按[文档结构](#2-文档结构)的必要条件与对应写法，更新版本演进路径和方向规划
4. 版本目标、范围或推进状态变化时，同步更新受影响的各部分
5. 发布后对照实际交付，更新版本完成状态
   与开发者确认未交付内容是否继续纳入后续版本规划

## 5 检查条件

- [ ] 当前状态与实际发布及推进情况一致
- [ ] 各计划版本的目标明确说明要达成的结果
- [ ] 各计划版本的纳入范围已经确认
- [ ] 同一版本在各部分的目标、范围与状态一致
- [ ] 版本完成状态与实际交付一致
- [ ] 各部分符合[文档结构](#2-文档结构)的必要条件与对应写法
