# 文档设计：testcase

## 1 文档定位

一个单元的黑盒测试方案，通过对外入口驱动，验证对外契约规定的行为
单元是具有明确对外边界的测试对象，可以是整个项目，也可以是项目内的一个模块

接口行为以 [interface](interface.md) 的对外契约为依据
用户交互行为以对应的交互设计为依据
命令与事件的黑盒、白盒测试归 [command](command.md) 与 [event](event.md) 的具体设计文件
模块内部机制的白盒测试归 [class-design](class-design.md)

## 2 文档结构

全文按[测试用例](../patterns/testcase.md) pattern 展开

```text
## 1 夹具
## 2 测试场景
## 3 测试用例
```

## 3 行文步骤

1. 确定测试单元与对外边界，列出需要验证的对外契约与交互行为
2. 根据测试对象的对外使用方式，明确执行环境、驱动入口与结果观察点
3. 从上述依据列出正常、失败、边界、状态变化与副作用的测试点
4. 按[测试用例](../patterns/testcase.md) pattern 编写

## 4 示例

参见测试用例 pattern 的[订单测试示例](../patterns/testcase.md#3-订单测试示例)与[意图识别评测示例](../patterns/testcase.md#4-意图识别评测示例)

## 5 检查条件

- [ ] 测试依据来自对外契约与交互设计，不从内部实现的分支或私有状态推导
- [ ] 通过对外入口驱动，断言契约规定的结果、副作用与不应发生的事
- [ ] 执行环境、驱动入口与结果观察点明确，能够执行用例并判定结果
- [ ] 满足[测试用例检查条件](../patterns/testcase.md#5-检查条件)
