# Doc Design: data-collection

## 1 Purpose

For people who analyze operational data, describe the sources, retrieval methods, and definitions of raw data

## 2 Structure

The body contains the following two chapters

| Chapter | Content requirements |
| --- | --- |
| 1 Data Sources | Explain where the raw data is and how to retrieve it |
| 2 Data Definitions | Describe the fields, meanings, formats, and necessary value constraints of the raw data |

Both parts can provide direct explanations or reference the corresponding content in existing docs
References must point to specific sources, retrieval instructions, or data definitions
For business data generated by the repo, reference the event details and data destinations in [instrumentation](instrumentation.md)

## 3 Writing Steps

1. Identify the raw data needed for operational analysis and clearly describe its sources and retrieval methods
2. Complete the corresponding data definitions so analysts can understand and use the raw data
3. Check the doc against the [Checklist](#5-checklist)

## 4 Example

For order data, "Data Sources" explains where to export raw order records and how to export them
"Data Definitions" explains the meaning, format, and value constraints of each field in the order records, or references an existing data contract

## 5 Checklist

- [ ] The raw data sources and retrieval methods are clear
- [ ] The raw data fields, meanings, formats, and necessary value constraints are complete
- [ ] References point to specific content
