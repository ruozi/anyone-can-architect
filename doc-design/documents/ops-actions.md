# Doc Design: ops-actions

## 1 Purpose

Describe permitted actions that change actual business operations for operations staff

## 2 Structure

Each chapter describes one action and includes the following content

| Content | Requirement |
| --- | --- |
| Basis for the action | Optional, explain the basis for choosing the action, with references to one or more analytical metrics or other business reasons |
| Procedure | Explain how to perform the action and confirm the result |

If a basis for the action is provided, place it before the procedure

## 3 Writing Steps

1. Organize the permitted operational actions, with a separate chapter for each action
2. If there is a basis for the action, explain it and add the relevant references
3. Write the procedure and the method for confirming the result
4. Check the doc against the [Checklist](#5-checklist)

## 4 Example

For example, use a separate chapter for adjusting business configuration to explain where to find the configuration, how to adjust it, and how to confirm that the changes have taken effect
If analytical metrics determine the adjustment, reference the corresponding metric chapters before the procedure and explain the basis for the adjustment

## 5 Checklist

- [ ] Each chapter corresponds to one permitted action that changes actual business operations
- [ ] The procedure and the method for confirming the result are clear
- [ ] If a basis for the action is provided, it is clear and the relevant references are valid
